## 5. 对比方法与判定规则（`scripts/compare-24h.mjs`）

- **运行方式**：两侧 tick 停止后对冻结库运行：
  `node scripts/compare-24h.mjs`（全量）或 `--fingerprint`（快速指纹）。
  连接：`LEGACY_DB_URI`（默认 mysql://legacy:legacy@127.0.0.1:3317/bloodwar）、
  `DEV_DB_URI`（默认 mysql://root:hot@127.0.0.1:3318/bloodwar）。
- **流程**：遍历两侧全部业务表（排除 `__snap_*`）→ 先做 count+CRC32 全列聚合指纹，
  指纹相同的表直接进「完全一致」清单；指纹不同的表逐行拉取做
  **多重集比较**（行序无关，逐行 JSON 键值计数差集）。
- **掩码规则**：列名匹配 `/time|_at$|_ts$|posttime|endtime|starttime|last/i` 且值为数字、
  落在窗口 `[startTs, 对比时刻] ± 120s` 内的值折叠为 `"<window>"` 后再比较
  （两侧 tick 相位差与结算时刻秒级摆动由此吸收）。
- **auto-inc 漂移**：information_schema 逐表 auto_increment 计数器差异单独列出
  （纯计数差**不算失败**）。
- **输出**：完全一致表清单、差异表清单（每表前 5 行 dev-only / legacy-only 样例）、
  auto-inc 漂移表、最终 `PASS/FAIL`（**PASS = 掩码后逐表多重集 0 差异，即无结算语义差异**）。
- 布置当时已用空窗与夹具窗口各验证一遍：481/481 全部一致，`PASS`。

## 6. 预期差异（已知、不视为端口回归，需人工裁决）与遗留风险

布置当时（T0+35min）实测运行 `compare-24h.mjs --start <T0>`：**475/481 表一致**，
6 张差异表全部落在下列已知项内：

1. **Curse 整点节奏（已知的移植偏差）**：原版 `date('is')<15` 让 3 秒 tick 在每小时
   前 15 秒最多跑 5 次（5 倍损失/奖励），dev 按小时去重只跑一次。实测 16:00 整点：
   legacy 落 6 行（1 次超仓惩罚 + 5 次忠诚警告）、dev 落 2 行（内容逐字一致）→
   `sys_report` uid 1002 行数差异为**预期结构差**（实测 +2/-6 样例即此）；之后每小时
   再各 +5/+1 行。`mem_state` state=10 的 value（排行重建时刻）同样 5 次 vs 1 次，
   且 `value` 列名不匹配掩码规则，以原始值差异出现（实测 1794124813 vs 1794124802）。
2. **城防队列 gate（原版 bug 的忠实保留差）**：原版 `UpdateUsersDeinforce` 的
   `WHERE state_endtime <= state_endtime <= unix_timestamp()` 恒真（先自比得 1，
   1 <= 时间戳恒真）→ legacy 在布设后第一个 tick 就把 mem_city_reinforce 全部结算
   （did1=10、did2=20 入 sys_city_defence，队列清空），且其 `delete from
   sys_city_defence where count=0` 是全局的（legacy 即时清了 13 行 0 库存行）；
   dev 按到期时间 16:57 才结算 A 并做同样的全局清理，B（T0+31h）留在途。
   → `mem_city_reinforce` / `sys_city_reinforcequeue` / `sys_city_defence` 的差异
   （实测 +1/-0、+2/-0、+15/-2）全部源于此，dev 注释（defence.tick.ts）亦明确记录该偏差。
3. **legacy 每次 tick 请求引导 global.php → SetCityBaseProduce 重算资源上限**：
   城池 209355 的 `wood/rock/iron_max=6010000、food_max=28810000、gold_max=120000000`
   被按建筑等级重导（twin 存档是 6000000/28800000/121000000，与 difftest 用例
   `troop tick settles transport arrival and return` 的 tables.ignore 注释一致）。
   → `mem_city_resource` 该行的 5 个 `*_max` 列为**永久预期差**（difftest 对此表
   亦按 ignore 处理）；其余列（含 food/wood 实值）一致。
4. **将领历练完成是随机的**：expAdd 含 `mt_rand(1,1000)`、奇遇事件三连掷、
   `cfg_name order by rand()` 等，两侧独立掷点必然分叉（sys_city_hero.exp、
   sys_report 内容、sys_inform、奖励表）。写入面已收敛到 1002/188128。
5. **Battle handler 未布置**：mem_maneuver 的结算在原版由易语言后端完成，
   legacy tick 替身（cfg_js.php）不调 upManeuver，布了必分叉；mem_battle 真实战斗
   布设复杂且战斗掷点随机。→ 24h 内 Battle 路径两侧同为空转。
6. **sys_king_expr（君主历练）未布置**；troop task 8（战场调遣）未布置（需完整
   战场状态机），task 7 已覆盖。
7. **世界刷新只在 dev 关闭**：dev 以 `WORLD_REFRESH_ENABLED=false` 启动（原版无此
   8 小时任务在 tick 链内）。若有人重启 dev 进程必须带同样 env，否则 mem_world
   8 小时后单侧生长。
8. **MySQL/容器重启风险**：legacy 几乎全库 MyISAM（cfg_common/cfg_page_time 为
   MEMORY 引擎，重启丢内容）；InnoDB 侧重启会丢 update_time。静置期间容器必须常驻。
9. **auto-inc 计数器漂移**：允许并单独列出（sys_report 两侧基线计数器本就相差 4，
   布置期探针又各 +1）。
10. 运维观察：`docker exec hot-legacy-php-1` 偶发 >2min 无响应（Docker Desktop 高负载），
   静置期检查一律走 DB 查询或 `docker top/stats`，不要 exec 进 php 容器。
11. 布置期探针残留：dev 侧 troop 900199 秒级结算产生的 sys_report 行已删、
   sys_city_soldier sid1 +10 已回冲（两侧均 50）；`mem_city_resource.food_army_use`
   dev 暂为 4466.67（按当时 60 兵重算的旧值），17:07 侦察返回触发两侧重算后同为
   4460（Σfood_use×count=6690 × 2/3）。
